# Codex 語境與驗證

## 啟動與輸入

- 依實際工具規格選欄位。MultiAgent V2 顯式使用 `fork_turns: "none"`。V2 的 `"all"` 繼承父歷史，省略預設為 `"all"`，舊欄位會被拒絕。若確認工具是 V1，顯式使用 `fork_context: false`。即使是內部審閱者，也在關閉繼承後傳入允許的作者材料，避免把先完成的評語一併傳下去。
- 啟動訊息只含角色任務與白名單資料。優先內嵌正文。文稿太長而須透過檔案傳入時，提供專用正文副本及精確路徑，勿將作者私下筆記混入正文包。注意附件、讀者設定、檔案名稱及主代理的後續訊息也可能帶入額外線索。
- 對話歷史繼承、檔案權限、工具、記憶和模型既有知識各有範圍。共享工作區可能仍可讀取非白名單檔案。僅靠任務指示約束讀取時，在報告標示「按資料包限制審閱」，只有實際驗證權限阻擋後才宣稱檔案隔離。
- 官方設定 `agents.max_concurrent_threads_per_session` 管理可同時開啟的子代理執行緒，主執行緒另計。Skill 按當前可用名額調度，保持三個子代理的設計上限。視工具確認已完成執行緒是否仍佔名額，按需要結束或關閉。

## 手動驗收

在首次確認部署或執行環境改變時，用合成資料驗證。記錄介面、版本、參數、工具權限、峰值名額及輸出。一般審稿毋須每次加跑測試。

1. **對話探針。** 先把隨機字串只放進父對話。以相同任務和同一個明示控制字串，分別向繼承及不繼承的子代理詢問兩個字串。兩者都應能回傳明示字串。父對話字串應只出現在繼承組。若繼承組也取不到，結果未能判定。只在代理初始輸入之外另有測試資料時，檢查它能否透過工具取回，獨立記錄檔案測試。
2. **批次獨立性。** 在第一批結果放入另一測試字串。核對第二批輸入及輸出，後者應可取得作者意圖及原定大綱，第一批結果應留在封存區。總編輯應在五份報告齊備後才取得全部結果，並與所有審閱者使用同版正文。
3. **編審品質。** 用含未定義術語、缺前提、未交代讀者痛點、缺比較證據及一項有據優點的合成稿。讓審閱者各指出至少一項有段落依據的角色發現。更改目標讀者後，應合理調整解釋門檻。總編輯應定位與原定大綱的差異，合理裁決相反意見。
4. **重複率與失敗處理。** 人工合併根因、位置及修訂目的相同的有效評語。重複率為合併前後的差值除以原有效評語數，無評語時標記無法計算。保留獨有發現，用兩種以上文類建立基線。模擬名額不足及某角色逾時，核對重試及缺件標示。
