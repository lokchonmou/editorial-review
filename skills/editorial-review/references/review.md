# 角色與報告規格

| 角色 | 材料 | 主要任務 |
| --- | --- | --- |
| Cold Reader | 正文、目標讀者 | 用讀者合理可有的知識檢查術語突現、指涉與背景缺口。定位首次出現和正文已有定義。 |
| Logic Reviewer | 正文、目標讀者 | 從正文建立反向大綱，檢查推論順序、因果、循環論證與前提缺失。 |
| Naive Reader | 正文、目標讀者 | 模擬推理力強、缺少指定領域先備知識的人。找出「為何值得關心」「為何採這個方案」及何處需要交代。 |
| Defender | 正文、目標讀者、作者材料 | 找出最有根據、值得保留的論點及成立條件。指出支持材料在正文或只在作者材料。 |
| Challenger | 正文、目標讀者、作者材料 | 提出有力反例、替代解釋、比較基準及待補證據。區分證據不足與已有反證。 |
| Chief Editor | 全部材料及五份獨立報告 | 比對原定與反向大綱，整合重複、裁決分歧、重排敘事，列出作者要決定及需補證據的事項。 |

各角色另收自己的任務說明。作者材料包括原始討論、作者意圖和原定大綱。外部三角色只使用傳入的正文與讀者設定，依文內線索提供可檢查的發現。工地巡邏報告中，「SLAM 首次出現沒有解釋」、「更快巡視何以帶來安全成效」及「現有攝像頭為何不足」是三項不同診斷。

## 寫作方法

- **Known–New Contract。** 確認新概念或主張出現時，目標讀者能從前文或合理先備知識建立承接。輸出位置、已知資訊、新資訊及缺失連結。按情況提早定義、補轉折或重排，並避免機械套用句式。[Gopen 與 Swan](https://www.cs.tufts.edu/comp/105-2015s/readings/sci.html)
- **反向大綱（Reverse Outline）。** 逐段記錄段號、實際主題、在全文的作用與依賴前提。遇到正文缺口，明列缺少甚麼。完成後才由總編輯比對原定大綱。[Purdue OWL](https://owl.purdue.edu/owl/general_writing/the_writing_process/reverse_outlining.html)
- **論證大綱（Argumentative Outline）。** 對每項核心主張追蹤理由、證據、推論橋樑、成立條件及重要反方。記下每個要件的來源與待補證據，據此擬定修訂次序。[Purdue OWL](https://owl.purdue.edu/owl/general_writing/academic_writing/historical_perspectives_on_argumentation/toulmin_argument.html)

## 回傳內容

審閱者回傳角色、稿件版本、段落定位或短引、發現與影響、具體行動。來源不明的內容標作待核實，避免補造資料。Logic Reviewer 另附反向大綱。

總編輯在合併後保留原角色和重要理由。優先處理影響全文主張、論證有效性或讀者理解的事項。若有相反建議，並列具體取捨、建議選項及理由。整理一個修訂次序，列出應保留的內容、要移動或補寫的資訊、待求證項目及作者要裁決的問題。
