# Editorial Review — Multi-Agent Writing Auditor

## 為甚麼開發這個 Skill？

目前我使用 AI 撰寫長篇文章的工作流程如下：

1. 與 AI 深入討論觀點、背景及論據。
2. 生成細化至三級標題的文章大綱。
3. 人工審查大綱及確認論述方向。
4. 由 AI 根據大綱撰寫全文。

然而，問題往往出現在第四步：AI 容易將各級標題視為獨立的內容填充任務，而不是一條完整的論證鏈。

因此，即使每個小節獨立閱讀都沒有問題，整篇文章仍可能出現以下缺陷：

- **概念突現（Concept Introduction）**：突然引入一個專業術語，但前文沒有任何鋪墊或定義。
- **論述斷層（Logical Gap）**：由觀點 A 跳到觀點 C，缺少中間推論 B。
- **局部合理、全局失衡（Local vs. Global Coherence）**：每個小節都有道理，但組合起來卻未能構成完整的論述。
- **語境流失（Context Loss）**：之前與 AI 討論過的重要觀點，在正式寫作時被遺漏或弱化。
- **虛假連貫性（False Coherence）**：AI 使用「因此」、「綜上所述」、「基於上述分析」等連接詞，掩飾實際上並不存在的邏輯關係。

**一份結構完整的大綱，並不保證能產出一篇論述連貫的文章。**

## 設計理念

另一個問題是，當作者長時間投入某個研究或項目，往往會將部分專業知識、背景資訊及隱含假設視為理所當然。

我在多年指導學生參與創新科技比賽的過程中，發現非工程背景的老師雖然未必具備相關技術知識，卻經常能憑藉良好的邏輯思維及敘事能力，指出工程背景的老師和學生所忽略的問題。

這些問題不一定源於技術錯誤，而是源於知識的詛咒（Curse of Knowledge）、專家盲點（Expert Blind Spot），甚至是先有方案、再尋找問題的事後合理化。

因此，我開發了這個 Skill，透過多代理審查（Multi-Agent Review）及語境隔離（Context Isolation），模擬不同知識背景、不同立場及不同審查職能的讀者，從多個角度審視同一篇文章。

## 六個專職 Agents

| Agent              | 角色定位       | 核心職責                                                     |
| ------------------ | -------------- | ------------------------------------------------------------ |
| **Defender**       | 正向論證者     | 理解作者原意，識別有價值的觀點，保留及強化合理論證，而非盲目認同作者。 |
| **Challenger**     | 反向論證者     | 主動質疑文章的觀點、證據及假設，尋找反例、論證漏洞及確認偏誤。 |
| **Cold Reader**    | 首次閱讀者     | 未曾參與原始討論，以首次閱讀文章的角度，檢查術語突現、背景資訊缺失及未經交代的概念。 |
| **Logic Reviewer** | 邏輯流程審查員 | 不預先閱讀原始大綱，直接根據文章建立 Reverse Outline，檢查論證鏈、因果關係、資訊排序及段落銜接。 |
| **Naive Reviewer** | 非領域專家讀者 | 模擬缺乏相關領域先備知識、但具備良好邏輯及批判思考能力的讀者，識別專家盲點、隱含假設及敘事障礙。 |
| **Chief Editor**   | 主審編輯       | 整合五個獨立 Reviewer 的審查結果，處理重複或互相矛盾的意見，判斷問題的嚴重程度，制定修訂策略，同時確保文章不偏離作者原意。 |

## Context Isolation：不同 Agent，不同資訊權限

這個 Skill 的核心並不只是增加 Agent 的數量，而是有意識地控制每個 Agent 所能獲取的資訊。

如果所有 Agent 都掌握相同的背景資訊，它們便可能共享相同的認知盲點，甚至自行補全文章中原本缺失的推論。

因此，各 Agent 採用不同的 Context Access Policy：

| Agent          | 原始討論 | 原始大綱 | 文章初稿 | 其他審查意見 |
| -------------- | -------- | -------- | -------- | ------------ |
| Defender       | ✅        | ✅        | ✅        | ❌            |
| Challenger     | ✅        | ✅        | ✅        | ❌            |
| Cold Reader    | ❌        | ❌        | ✅        | ❌            |
| Logic Reviewer | ❌        | ❌        | ✅        | ❌            |
| Naive Reviewer | ❌        | ❌        | ✅        | ❌            |
| Chief Editor   | ✅        | ✅        | ✅        | ✅            |

所有 Reviewer 均以同一版本的文章進行獨立審查，避免受其他 Agent 的意見影響。最後才由 Chief Editor 統一整合及裁決。

## Target Audience

不同文章的目標讀者具有不同的知識背景及閱讀目的。因此，Skill 將 Target Audience 設為可配置的輸入參數。

例如：

- 學術論文：相關或其他研究領域的學者。
- 創新科技比賽報告：非工程背景的評判。
- 學校政策文件：未曾參與政策制定的教師。
- 技術文件：首次接觸該系統的工程師。

審查的目的並非要求所有文章都能讓任何人理解，而是確保文章為其目標讀者提供足夠的資訊、合理的論證及清晰的閱讀路徑。

## 核心目標

Editorial Review 並不是另一個 AI 文章生成或文字潤飾工具，而是一個面向長篇文章的品質保證系統（Quality Assurance System）。

它不單關注文章是否寫得流暢，更關注：

- 作者真正想表達的內容，有沒有完整傳達？
- 文章的論證是否成立？
- 讀者能否在沒有參與前期討論的情況下理解文章？
- 每個段落是否對整體論述具有實質貢獻？
- 文章是否具備真正的連貫性，而非僅僅依靠語言上的流暢？

**The goal is not merely to make AI-generated writing sound better, but to make it think better, argue better, and communicate better.**
